# 0.2.0 — 2026-09-23

## Added

- **`tests/tools/tool-contract.test.ts`** ([#20](https://github.com/cyanheads/national-parks-mcp-server/issues/20)) runs all six tools through `runToolContract`, covering argument rejection, declared-contract errors, the upstream-failure envelope, the rendered enrichment trailer, and catalog prose.

## Changed

- **Breaking: `nps_find_campgrounds` amenities are `boolean | null`** ([#21](https://github.com/cyanheads/national-parks-mcp-server/issues/21)). `null` means NPS published no value (`""`, `[]`, or only blank elements), where it previously read `false`; `rvAllowed` is `null` when `accessibility.rvAllowed` is empty, and `format()` renders `Unknown`, never `No`.
- **Breaking: `nps_get_park` `directionsInfo` / `directionsUrl` are absent, not `null`, when `fields` excludes `directions`** ([#14](https://github.com/cyanheads/national-parks-mcp-server/issues/14)). Both left `required` in the output schema; `null` now means only "requested, and NPS publishes none".
- **Malformed park codes, state codes, and dates return `-32007` with a tool reason on every tool, instead of `-32602`** ([#12](https://github.com/cyanheads/national-parks-mcp-server/issues/12)). The schema `pattern`s are gone from `inputSchema`; each handler throws `invalid_park_code` / `invalid_state_code` / `invalid_date` with its declared recovery before any upstream call. `nps_get_park` gains `invalid_park_code` (the message names only the malformed codes), `nps_get_activities` gains both code reasons, and `nps_find_events` checks `YYYY-MM-DD` shape under `invalid_date`. An empty string counts as omitted.
- **`nps_get_alerts` no longer re-sorts alerts** ([#11](https://github.com/cyanheads/national-parks-mcp-server/issues/11)) — `/alerts` already returns them `lastIndexedDate`-descending, and that upstream order is the tool's ordering contract.
- **Tool descriptions, field descriptions, and error `when` text state the caller-facing contract** ([#17](https://github.com/cyanheads/national-parks-mcp-server/issues/17)), without implementation mechanics or weather-server pointers. Runtime notices say "NPS reported: …" instead of "Upstream reported: …".

## Fixed

- **`truncated` reaches both client surfaces** ([#9](https://github.com/cyanheads/national-parks-mcp-server/issues/9)) — the five list tools declare it in `enrichment`, so a capped page carries `structuredContent.truncated: true` and a `**Truncated:** true` trailer line. `totalCount` now renders as `**N total**`.
- **Amenity values that mean "not available" read `false`** ([#13](https://github.com/cyanheads/national-parks-mcp-server/issues/13)) — `No`-led values (`No Toilets`), `not potable` / `non-potable`, and NPS's comma-split `["Water", " but not potable"]`. A real positive beside a negative stays `true`.
- **`weatherOverview`, `directionsInfo`, and fee/pass `description` on `nps_get_park` are plain text** ([#15](https://github.com/cyanheads/national-parks-mcp-server/issues/15)) when NPS sends markup; markup-free values keep their line breaks. HTML stripping keeps prose such as `p < 0.05` and removes a tag reassembled around an inner one (`<scr<b>ipt>`).
- **`nps_get_alerts` gives no all-clear when a `category` or `query` filter matched nothing** — the notice says alerts outside those filters may still be active.
