# 0.2.1 — 2026-10-08

## Changed

- **Tool error results close with `request <id>` and carry `data.requestId`** (mcp-ts-core 0.13.10, [cyanheads/mcp-ts-core#576](https://github.com/cyanheads/mcp-ts-core/issues/576)). The id is always a framework-generated token; the client's JSON-RPC id is logged as `jsonRpcId` (0.13.12, [cyanheads/mcp-ts-core#584](https://github.com/cyanheads/mcp-ts-core/issues/584)).
- **Arguments are repaired before validation** (0.13.14, [cyanheads/mcp-ts-core#707](https://github.com/cyanheads/mcp-ts-core/issues/707), [#602](https://github.com/cyanheads/mcp-ts-core/issues/602), [#616](https://github.com/cyanheads/mcp-ts-core/issues/616)). A numeric or boolean string for a number or boolean field (`limit: "3"`), a lone string for a list field (`parkCode: "yose"` on `nps_get_park`, `fields: "fees"`), and `null` at an optional key (dropped, so the default applies) are accepted. A boolean for a number field (`limit: true`) is still rejected.
- **An integer sent for a string field becomes its digits** (0.13.9, [cyanheads/mcp-ts-core#487](https://github.com/cyanheads/mcp-ts-core/issues/487)); the `-32602` rejection is bounded in size (0.13.14, [cyanheads/mcp-ts-core#648](https://github.com/cyanheads/mcp-ts-core/issues/648)).
- **Error `data` no longer carries server stack traces** (0.13.7, [cyanheads/mcp-ts-core#519](https://github.com/cyanheads/mcp-ts-core/issues/519)), **request context fields** (0.13.8, [cyanheads/mcp-ts-core#548](https://github.com/cyanheads/mcp-ts-core/issues/548)), or **`rootCause`** (0.13.13, [cyanheads/mcp-ts-core#644](https://github.com/cyanheads/mcp-ts-core/issues/644)).
- **Upstream fetch errors and log records name the NPS URL by origin only** (`https://developer.nps.gov/…?…`; 0.13.12, [cyanheads/mcp-ts-core#626](https://github.com/cyanheads/mcp-ts-core/issues/626)).
- **`ctx.log` lines mirrored to the client honor `MCP_LOG_LEVEL` and mask sensitive fields** (0.13.11, [cyanheads/mcp-ts-core#621](https://github.com/cyanheads/mcp-ts-core/issues/621), [#630](https://github.com/cyanheads/mcp-ts-core/issues/630)).
- **The six tools no longer forward `ctx.recoveryFor(...)`**; the framework fills each declared recovery hint from the tool's `errors[]` contract (0.13.10, [cyanheads/mcp-ts-core#579](https://github.com/cyanheads/mcp-ts-core/issues/579)). The hint text callers receive is unchanged, and the tests assert it through `runToolContract`.
- **`server.json`: the `streamable-http` npm entry sets `MCP_TRANSPORT_TYPE` to `http`**, so a registry client launching it gets the HTTP transport (it previously started stdio). Both npm entries use `runtimeHint: "npx"` and drop the `run start:stdio` / `run start:http` arguments (0.13.11, [cyanheads/mcp-ts-core#622](https://github.com/cyanheads/mcp-ts-core/issues/622)).
- **Docker image installs production dependencies in a `deps` stage on `$BUILDPLATFORM`** instead of running `bun install` on the target platform (0.13.10, [cyanheads/mcp-ts-core#575](https://github.com/cyanheads/mcp-ts-core/issues/575)), and drops musl-only native packages (0.13.11, [cyanheads/mcp-ts-core#608](https://github.com/cyanheads/mcp-ts-core/issues/608)). The image no longer sets `MCP_FORCE_CONSOLE_LOGGING`.
- **Bun 1.4.0 → 1.4.2** in `packageManager`, the Docker base images, and the README badge (0.13.7).
- **`.env.example`** gains the framework block (`MCP_REQUEST_STATE_KEY`, `LOG_TOOL_FAILURE_PAYLOADS`, `LOG_LLM_INTERACTIONS`, the OTLP endpoint overrides) and an `MCP_HTTP_HOST` default of `127.0.0.1`; the README env table lists `LOG_TOOL_FAILURE_PAYLOADS`.
- **`.gitignore` ignores every `.env*` file** except `.env.example`, `.env.template`, and `.env.sample`; `.dockerignore` excludes `.env*` and the MCP Registry token files; `.mcpbignore` excludes `docs/idea.md`, `logs/`, `.cache/`, and `coverage/`.
- **`.github/workflows/codeql.yml`** analyzes `actions` and `javascript-typescript` in a matrix, each uploading under `/language:<language>`.
- **README** tool sections are condensed, the MCP SDK badge reads `^2.2.0`, and a feature line notes that empty results carry a notice, not an error.
- **`CLAUDE.md` / `AGENTS.md`** track the 0.13.14 `ctx` and error-contract reference, the `audit:fix` script, and the single-workflow CI rule.
- **Framework skills and scripts** (`devcheck`, `lint-mcp`, `lint-packaging`, `check-skill-versions`, `check-framework-antipatterns`, `release-github` with `--check` tag validation, `install-otel`, `prune-musl-packages`) are synced with mcp-ts-core 0.13.14; `docs/tree.md` is regenerated.
