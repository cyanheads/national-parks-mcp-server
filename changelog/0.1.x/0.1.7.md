# 0.1.7 — 2026-09-20

## Changed

- **`@cyanheads/mcp-ts-core`** `^0.12.3` → `^0.13.6`, which changes four things a caller sees:
  - An argument the six `nps_*` tools reject now comes back as a structured error envelope classified `InvalidParams` (`-32602`), carrying `data.reason: "invalid_arguments"` and a `data.recovery.hint` derived from the schema, in place of the raw Zod diagnostics. The hint rides `content[]` as a `Recovery:` line.
  - Tool error text closes with `(reason <reason> · not retryable)` whenever the error carries a reason or a boolean `retryable` — every `ctx.fail` throw across the six tools does.
  - A caller that disconnects mid-call classifies `RequestCancelled` (`-32011`) and logs at `info`, where it previously surfaced as an internal error or a timeout.
  - **Upstream error `data` no longer carries the request URL.** This matters here: an NPS Data API request URL carries `NPS_API_KEY` in its query string. The message still names the host.
- **A root key the client adds, or one that case-folds to exactly one declared field, is accepted** — an ordered pre-validation step drops or rewrites it before the tool's schema runs. `inputSchema` is unchanged and no tool declares its own `inputAliases`.
- **`sessionMode: 'stateless'` is declared in `src/index.ts`** rather than left to `MCP_SESSION_MODE`'s `auto` default, which resolved to stateful. No tool calls `ctx.requestInput`, so `require: 'stateful'` is deliberately not set; a meaningful `MCP_SESSION_MODE` still wins.
- **The development skill tree moved from `skills/` to `framework-skills/`**, so a plugin install no longer hands these skills to the installing agent.
- **Breaking: Bun** now requires `>=1.4.0` (was `>=1.3.0`).

## Fixed

- **Plugin installs no longer hardcode a placeholder `NPS_API_KEY`.** Both manifests shipped `"NPS_API_KEY": "your-api-key"` in `env`, which the client set on the child process over whatever the user had exported. `.claude-plugin/plugin.json` now declares the key under `userConfig` and references `${user_config.nps_api_key}` so Claude Code prompts for it; `.codex-plugin/mcp.json` lists it under `env_vars` so Codex forwards it from the user's environment.

## Security

- **`stripHtml()` decodes each character reference exactly once** ([#18](https://github.com/cyanheads/national-parks-mcp-server/issues/18)) — it decoded `&amp;` ahead of the references that follow it, so an `&` the first replacement produced was decoded again and the escaped text `&amp;lt;` surfaced as `<`. Decoding is now a single pass over a lookup. Affects NPS free-text fields on `nps_get_activities` and `nps_find_events`.
